## 当前实现和已经定下的边界

- **运行协议**：[Agent 入口](../career_agent/agent.py) 为 `async handle(command, services, emit)`。真实分发已有 `chat / parse_resume / extract_jobs`；其余动作目前有演示流程，真实入口返回未实现。演示资料在 [demo.py](../backend/demo.py)。接口以 [contracts.py](../backend/contracts.py)、[schemas.py](../backend/schemas.py) 和 [运行服务](../backend/services/run_service.py) 为准。[项目参考代码目录](../项目参考代码目录.md) 的 2.2–2.5 节适合查开发交接；其中部分旧文案或规划早于最新岗位必填规则。原始设计、进度记录、记忆设计笔记有历史版本，遇到差异先核对当前源码和最新用户决定。
- **四种上下文**：`snapshot` 是发起时冻结的业务资料；`state` 是同一运行上次交回的结构化进度；`history` 是已发生的用户/助手消息；本轮输入统一读 `human_input["text"]`，首次 `decision="start"`，续接由 `answer/confirm/reject/finish` 表达。文件或岗位 ID 在 `command.input`，单纯上传的 ID 不写成用户聊天消息。Agent 暂停时交回完整 state，应用创建一次性输入 ID。非面试的 finish 由应用结束，面试的 finish 会交回 Agent。一次只允许一个活动运行。
- **历史、摘要、用量**：应用在内存中按 `(session_id, action)` 存储；缺少 session_id 时以 run_id 兜底。普通聊天在同一页面打开期间跨页面、岗位、报告共用历史；刷新/新标签页生成新会话。每条消息仅 role/content，不按岗位 ID 分组，不落库、不截断或淘汰。摘要字段和覆盖条数的读写已接通，自动摘要时机与生成策略留给用户。模型 usage 取实际响应，传递本次及上次模型调用用量，不累计整次运行。应用回执不算模型调用。
- **历史的最新特例**：`services.clear_history(command)` 是同步方法，可清除当前分组的消息、摘要及 command 副本。当前 [agent.py](../career_agent/agent.py) 只在 `extract_jobs` 的 start 调它；A 图之后，B 图从空历史开始，B 的多轮 answer 继续使用全部 B 问答。此前曾讨论全局 start 清空并复现普通聊天记忆丢失；当前 HEAD 已缩小条件。不要根据那次诊断再次改代码。两场模拟面试是否清历史，是用户明确推迟的决定。
- **聊天**：[chat.py](../career_agent/chat.py) 使用 DeepSeek、异步 `ainvoke` 和 `function_calling`，关闭思考模式以支持指定工具，保留原响应用量。工具参数决定 reply/question/proposal，唯一展示文字为 message，proposal 携带结构化修改。回复正文可为空。只有缺必要信息才追问；对象、字段及新值明确直接提案，由应用展示确认/拒绝。后端校验修订号并只保存一次，聊天 Agent 不重复写库。
- **简历**：[正式实现](../career_agent/parse_resume.py) 处理 PDF/DOCX，读取正文及页码、段落和表格行位置，使用 `ProfileData`。基于扁平的 `command.state or command.snapshot["profile"]["data"]` 合并模型显式字段后重新校验。`exclude_unset=True` 只排除模型省略的字段，模型明确返回空值仍会覆盖旧值。缺项一次列出、允许分次回答；完成的 `profile_draft.data` 直接是画像字典，确认表单才入库。当前正式版本每轮重新读文件；纯扫描 PDF 需先 OCR。早期 AI 简历参考版及其专属测试已移除，不要按旧交接找回。
- **个人资料**：画像与求职条件合并在一个 profile。已移除 headline、commute_limit_minutes，学历与大学专业 major 分开。除来源依据 evidence 外，14 个业务字段确认时均必填，含个人简介和出行偏好。0 年经验合法；出行偏好值用「公共交通」「驾车」，旧英文值有迁移兼容。未来通勤报告路线键仍是 public_transit/driving。Pydantic 模型字段有中文 title，缺项检查使用模型元数据。前端为只读方式展示提取依据。
- **岗位导入与保存**：入口只有截图与粘贴原文；一图一次运行、一次初始 LLM 提取、一个岗位，补充回答可另调模型。前端逐张处理；返回 `kind="job_drafts"`（沿用复数命名），`data` 直接是单个 JobData 字典。原件上传与岗位正式入库是两个动作。新增、编辑都要补齐 company、title、city、address、salary_min、salary_max、job_description、job_requirement、experience_years、education。草稿可以暂缺，正式保存拒绝空白和“未披露”。月薪为元/月，数值正且上下限有序；明确不限经验填 0，“3—5年”取最低 3。此前「岗位可带盲区/未披露直接保存」已被用户纠正。
- **折叠正文**：正式 [extract_job.py](../career_agent/extract_job.py) 先处理 parsed 为 None 的失败，合并草稿再校验 JobData。显式 `complete=None` 触发 `JOB_TEXT_FOLDED`，提示展开重新截图。多图剩余队列由用户点「跳过并继续下一张」继续，普通失败或 413 停止整批。只针对岗位正文折叠，其他区域“查看更多”不应单独触发。用户亲测折叠样例返回 None；模型漏传时字段默认“完整”是已有契约边界，用户接受现状。真实提取用 [local_ocr.py](../career_agent/tools/local_ocr.py) 识别全文和地图目标文字；[ai_extract_job.py](../career_agent/ai_extract_job.py) 为独立参考，正式入口导入用户版本。
- **依据、去重的意愿与现状应分开看**：岗位 evidence 为只读字典列表（document_id、locator、text）。当前保存服务用公司/职位筛候选，再比较业务字段与证据截图 ID 集合，匹配时可合并摘录；不同截图 ID 分开。旧 jd_text 整段迁至 job_description，多来源旧记录需人工整理，报告保留原快照。用户后来明确表示不要求 Agent 把十六进制文件 ID 强行绑到 evidence，内容相同的岗位合并可以接受。最终要求「就现在这样什么都不改」，先后提交代码；尚无改动授权去重做来源关联或去重策略。[保存逻辑](../backend/services/job_service.py)

## 编码规范（完整保留）

### 编码前思考

- 明确说明关键假设，不隐藏困惑。
- 存在影响实现的多种解释时，呈现差异和权衡，先澄清，不默默选一种。
- 有更简单的方法时提出异议或替代方案。
- 关键需求不清楚时，停止依赖该需求的修改并澄清；不依赖该需求的工作可继续。

### 简洁优先

- 用最少的代码解决当前问题，不添加要求之外的功能。
- 不为一次性代码创建抽象。
- 不添加未要求的灵活性、配置项或推测性的兼容方案。
- 不为不可能发生的场景添加错误处理，不为不会出现的异常添加校验，不堆叠重复校验。
- 如果 200 行能用 50 行清楚解决，就简化；以资深工程师是否会认为过于复杂为判断标准。

### 精准修改

- 每一行修改都必须能直接追溯到本次请求。
- 不顺手修改相邻代码、注释或格式，不重构没有问题的部分。
- 匹配项目现有风格，即使自己偏好不同写法。
- 删除因本次修改而变得无用的导入、变量或函数。
- 发现原有无关死代码或问题，可以报告，不擅自删除或修复。
- 保留用户已有修改，不覆盖与本次任务无关的工作。

### 目标驱动执行

- 优先从输入约束和流程设计上避免 bug，不在底层堆砌冗杂校验作为补丁。
- 多步骤任务先给简短计划，每步都对应明确的验证方式。
- 修复 bug：先建立能复现问题的测试或验证，再确认修复有效。
- 添加验证：先验证无效输入会导致的问题，再确认实现满足要求。
- 重构：确认改动前后行为一致，相关测试通过。
- 验证针对真实风险，不为凑数量编写重复实现的测试。
- 以可验证的完成标准循环推进；汇报实际改动、实际验证与未覆盖范围。

## 当前用户要求保留的执行硬约束

- 单请求 body 上限为 48 MiB；超出返回 413 会导致整轮失败且不会自动恢复。遇到 413 不重试同一请求，直接告知用户。
- 内联截图每张可能为 0.3–6.7 MB，却只约计 1024 tokens；禁止用 token 数判断请求体积安全余量。
- 一次只截一张，只截必要区域，获得结论即停止；能用日志或文本验证的，不截图。
- 需要视觉验收（computer-use / 浏览器截图）时，用 `spawn_agent` 委派子代理；父线程只接收文字，不自行调用截图工具。子代理报告必须包含结论与关键文字或坐标，不能只说“看起来正常”。
- 子代理完成即关闭；若当前环境没有关闭工具，明确说明能力限制，不声称已关闭，也不擅自用归档、删除或中断替代关闭。
