## 两个工程当前的分工

**工作台。** 导航只有简历画像和岗位池。岗位详情、岗位评估、模拟面试是三个同级折叠区，各自显示执行记录。可以删除单份评估，也可删除岗位并保留历史快照。题库管理、MD 上传和旧题目表已经移除，个人记忆、岗位截图和简历仍在工作台。

每次评估一个 JD。模型返回匹配判断及两处依据；程序关联岗位 ID，对必备要求等权计分。「符合／部分符合／不符合／资料不足」计 1／0.5／0／0，无可判断项时分数为空。最有利经历和最不利关键要求均用字符串。首次匹配后搜索起终点候选，同屏选择后只查公交和驾车，不重算匹配分。真实模拟面试选题和追问尚待接入。[评估入口](../career_agent/evaluate.py) · [工作台使用说明](../README.md)

**知识库。** 上传原件按哈希复用，文档保存在 `data/originals`。点「整理草稿」时按 `documents.questions_llm_confirmed` 决定是否拆题；已确认就展示正式题目，即使全部仍是 pending。人工确认时，题目与文档标记在同一事务提交。题号 `sort_order` 按文档内最后确认的排列保存，筛选和重开都保留原号。答案编辑时保留 Markdown 原文，预览和已确认列表在本地渲染。

保存只写 MySQL，点击「全量重建向量索引」才由后端读取全库题目并交给 Agent。一题一个向量，检索文本为题干加标签，ID 为 `question_id`。**按钮语义与用户版 Agent 实际行为有差异**：当前 `rebuild_index` 只添加缺失 ID，使用 LangChain Chroma 的 `persist_directory`；早期独立 Chroma HTTP 服务和官方 SDK 全量 upsert 的实现只能作为历史参考。当前 `search_ids(topic, limit)` 是两参数；后端按召回排名读取 MySQL 中仍存在且已索引的题目，返回最新答案和出处，过滤后可少于 limit。[当前用户版 RAG](../../knowledge_service/knowledge_agent/rag.py) · [知识库服务](../../knowledge_service/backend/service.py) · [知识库开发交接](../../knowledge_service/后端与Agent开发交接.md)

## 编码规范（完整保留）

### 编码前思考

- 明确说明关键假设，不隐藏困惑。
- 存在影响实现的多种解释时，呈现差异和权衡，先澄清，不默默选一种。
- 有更简单的方法时提出异议或替代方案。
- 关键需求不清楚时，停止依赖该需求的修改并澄清；不依赖该需求的工作可继续。

### 简洁优先

- 用最少的代码解决当前问题，不添加要求之外的功能。
- 不为一次性代码创建抽象。
- 不添加未要求的灵活性、配置项或推测性的兼容方案。
- 不为不可能发生的场景添加错误处理，不为不会出现的异常添加校验，不堆叠重复校验。
- 如果 200 行能用 50 行清楚解决，就简化；以资深工程师是否会认为过于复杂为判断标准。

### 精准修改

- 每一行修改都必须能直接追溯到本次请求。
- 不顺手修改相邻代码、注释或格式，不重构没有问题的部分。
- 匹配项目现有风格，即使自己偏好不同写法。
- 删除因本次修改而变得无用的导入、变量或函数。
- 发现原有无关死代码或问题，可以报告，不擅自删除或修复。
- 保留用户已有修改，不覆盖与本次任务无关的工作。

### 目标驱动执行

- 优先从输入约束和流程设计上避免 bug，不在底层堆砌冗杂校验作为补丁。
- 多步骤任务先给简短计划，每步都对应明确的验证方式。
- 修复 bug：先建立能复现问题的测试或验证，再确认修复有效。
- 添加验证：先验证无效输入会导致的问题，再确认实现满足要求。
- 重构：确认改动前后行为一致，相关测试通过。
- 验证针对真实风险，不为凑数量编写重复实现的测试。
- 以可验证的完成标准循环推进；汇报实际改动、实际验证与未覆盖范围。

## 当前用户要求保留的执行硬约束

- 单请求 body 上限为 48 MiB；超出返回 413 会导致整轮失败且不会自动恢复。遇到 413 不重试同一请求，直接告知用户。
- 内联截图每张可能为 0.3–6.7 MB，却只约计 1024 tokens；禁止用 token 数判断请求体积安全余量。
- 一次只截一张，只截必要区域，获得结论即停止；能用日志或文本验证的，不截图。
- 需要视觉验收（computer-use / 浏览器截图）时，用 `spawn_agent` 委派子代理；父线程只接收文字，不自行调用截图工具。子代理报告必须包含结论与关键文字或坐标，不能只说“看起来正常”。
- 子代理完成即关闭；若当前环境没有关闭工具，明确说明能力限制，不声称已关闭，也不擅自用归档、删除或中断替代关闭。
