# 求职决策 Agent · 前后端工作台

需配合后端独立RAG题库使用：https://github.com/liushuangxi98/knowledge_service

本机单用户应用：原生 HTML/CSS/JavaScript + FastAPI + MySQL。浏览器地址为 `http://127.0.0.1:8000`。

**工作台提供资料确认、岗位池、行内评估/面试及固定联调样例。** 真实入口已接通聊天、简历提取、单岗位提取和岗位匹配分析。岗位评估根据已保存画像逐项核对要求并给出材料覆盖分；使用高德查询从画像通勤起点到该岗位办公地址的单程公交和驾车路线。真实面试按岗位和简历规划考点，主问题由模型从知识库检索结果中选一道原题，页面展示原文和题号。追问可结合用户作答现场提出。

## 在 PyCharm 中运行（推荐）

前端由 FastAPI 直接提供，**只运行根目录的 `main.py`，前后端就一起启动**。不需要另外启动前端服务或执行 npm 命令。

1. 用 PyCharm 打开项目根目录 `D:\study\ai_project\job_search_agent`。
2. 在 **Settings → Python → Interpreter** 中选择已有解释器：`D:\study\ai_project\job_search_agent\.venv\Scripts\python.exe`。不同版本也可能显示为 **Project → Python Interpreter**；若未列出，添加本地已有解释器并选择这个文件。
3. 确认本机 MySQL 服务已启动，根目录 `.env` 已填写连接信息。你此前配置好的 `.env` 可以继续使用。
4. 右键根目录 **`main.py` → Run 'main'**。调试时选择 **Debug 'main'**，即可在业务服务或 Agent 接入处打断点。
5. 浏览器打开 **http://127.0.0.1:8000/** 使用前端；**http://127.0.0.1:8000/docs** 查看和测试后端接口。

运行配置的脚本路径为根目录 `main.py`，工作目录为项目根目录，参数留空。代码会自动读取根目录 `.env`，无须在 PyCharm 中逐个配置数据库环境变量。

首次在新环境使用时，在 PyCharm 的 Terminal 中依次运行 `.\setup.cmd`、填写 `.env`、运行 `.\init_db.cmd`，再按上述步骤运行 `main.py`。本机已安装依赖并初始化数据库后，不必重复这些步骤。数据库初始化也可使用普通 Python 运行配置：将运行目标选为 **模块 `backend.init_db`**，参数填写 `--create-database`，工作目录选择项目根目录。

**从旧版升级个人资料结构时**，先停止正在运行的应用，在项目终端运行以下命令，再启动 `main.py`：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m backend.init_db
```

初始化入口会验证并将旧 `preferences` 合并进 `profile`，提交后移除旧列。合并失败会回滚，删列失败可安全重跑。账号需要 ALTER 权限。原修订号、确认标记和历史报告快照保留，后续初始化可重复执行。

旧版固定画像 ID 的数据库升级时，先停服务，运行一次上述初始化命令，再启动。已有画像沿用原 ID、内容和修订号；新画像首次保存时由数据库生成 ID，编辑沿用该 ID，删除后画像行被移除。空表可直接打开填写。

初始化会将出行偏好 public_transit/driving 转为“公共交通”/“驾车”。旧画像也可直接在新版打开。下次保存或运行初始化命令时，当前画像的 `headline` 和 `commute_limit_minutes` 会被清理；`major`（大学专业）留待本人补齐后确认。

岗位提取依据改为 `evidence=[{document_id, locator, text}]`，每个岗位只关联一张截图。初始化会迁移旧单来源岗位；若发现旧岗位关联多张资料或非截图资料，会提示先人工整理，保留原数据。

修改 Python 后停止并重新 Run/Debug；修改 HTML/CSS/JS 后刷新浏览器即可。停止时点击 PyCharm 的 Stop。若提示端口 8000 被占用，先停止之前通过 `start.cmd` 或另一个 Run 配置启动的本项目服务。

操作入口参考 JetBrains 文档：[选择已有虚拟环境](https://www.jetbrains.com/help/pycharm/creating-virtual-environment.html)、[直接运行 Python 文件](https://www.jetbrains.com/help/pycharm/running-without-any-previous-configuring.html)。

## 使用 Windows 脚本启动

环境要求：Windows、Python 3.13、MySQL 8.0。前端无 Node 构建步骤、无 CDN。

1. 首次运行 `setup.cmd`，创建项目虚拟环境并安装依赖。
2. 复制 `.env.example` 为 `.env`，填写 MySQL 用户名和密码。已有 `.env` 不会被启动脚本覆盖。
3. 运行 `init_db.cmd`，创建项目库和缺失表。默认库名为 `job_search_agent`，不清空已有记录。
4. 双击 `start.cmd`，保持窗口打开，在浏览器打开上方地址。按 Ctrl+C 停止。

如果数据库账号没有建库权限，先由数据库管理员创建项目库，再运行：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m backend.init_db
```

接口文档启动后可在 `/docs` 查看。模型、高德 Key 在此前后端阶段都不需要。

## 从哪里开始使用

- 工作台有 **简历画像** 和 **岗位池** 两个入口，默认进入岗位池。
- 简历画像合并求职条件。姓名、学历、大学专业、工作年限、技能、工作经历、项目经历、求职方向、目标城市、通勤起点、期望月薪范围、个人简介和出行偏好全部补齐后，一次确认保存。
- 上传简历或招聘资料后先提取并核对草稿；原始文件已上传不代表业务资料已确认入库。真实提取未接入时会明确提示，固定样例标记为模拟数据。
- 岗位职责、任职要求、最低工作年限和学历分别保存；十个业务字段须补齐后保存，明确不限工作经验填 0；截图正文折叠时可跳过当前图并继续队列。个人核心资料仍须补齐。
- 在岗位行内点击评估，展开查看独立匹配分、要求与经历的对应依据、优势、差距及通勤时间/距离/路线；不再计算薪资分、通勤分、总分或排名。
- 在岗位行内开始模拟面试。真实模式需要先启动本机 8200 知识库服务并完成题目索引。预算为 5 道主问题：岗位与简历交集 3 道、简历经历 1 道、岗位扩展 1 道。开场确定考点和顺序。若某考点没有合适的单一原题，则跳到下一考点。回答吃力时，面试官可以围绕原考点用更具体、更简单的问题追问；追问仍归入当前主问题。作答不限时，每题提示默认折叠。题意不清时可直接输入想了解的范围或条件，面试官补充说明后继续原题；报告可回看这段交流，并结合澄清内容做复盘。完成计划或点击提前结束后生成报告。未提交的回答不计入报告，已答题目的点评和考点总结在结束后统一展示。
- 题库由单独的应用管理，请直接打开 [独立知识库平台](http://127.0.0.1:8200/)。在同级的 `knowledge_service` 工程中初始化数据库并运行 `main.py`，详见[平台使用说明](../knowledge_service/项目使用说明.md)。原件和题目保存在知识库自己的数据库及文件目录。
- 右下角聊天入口关联当前岗位、报告或页面。修改提案确认后保存，拒绝则不写入。

## 模拟与真实模式

`.env` 中 `AGENT_MODE=demo` 使用固定联调样例。页面始终显示模拟标识，顶部可以选正常、等待输入、部分结果和失败场景。**样例不会理解上传文件、不会评价你的回答，也没有查询真实通勤。** 演示岗位与模拟面试题会明确写出虚构或固定示例说明。

`AGENT_MODE=real` 读取你编写的 `career_agent.agent.handle`。缺少该入口时，真实请求返回 `503 AGENT_NOT_CONNECTED`，不会回退到模拟结果。切换配置后重启服务。真实通勤使用本地 .env 的 AMAP_API_KEY（高德 Web 服务 Key）。匹配完成后，在同一张表单选择通勤起点和办公地点。每端只有一项也需确认；某一端没有候选时，直接返回已完成的匹配分析并注明缺失地点。确认两个地点后直接查路线，沿用本次匹配分。缺少 Key 或部分路线不可用时仍可查看匹配结果。

接入说明见 [Agent 接口约定](docs/智能体接口约定.md)。本轮工作台改造不扩展真实 Agent 能力；后续实现按更新后的草稿和报告字段对接。

## 文件分工

| 位置 | 职责 |
| --- | --- |
| `backend/app.py` | 应用装配、生命周期和静态页面服务 |
| `backend/api/` | 接口层：接收 HTTP 参数、注入服务、返回响应 |
| `backend/services/` | 业务层：资料校验、修订冲突、事务、文件和运行流程 |
| `backend/repositories/` | 数据访问层：在当前 Session 中执行 SQL/ORM 操作 |
| `backend/models.py`、`backend/database.py` | MySQL 表模型、连接池和初始化 |
| `backend/agent_gateway.py` | 唯一的真实 Agent 接入位置 |
| `backend/contracts.py`、`backend/services/run_service.py` | Agent 契约、内存运行、事件和人工确认 |
| `backend/demo.py` | 固定联调数据，非 Agent 实现 |
| `frontend/` | 简历画像和岗位池、岗位行内评估/面试和历史结果、全局聊天 |
| `tests/` | 应用边界、MySQL、浏览器及 Agent 对接流程测试，不代表真实模型效果评测 |
| `data/` | 本机上传文件及脱敏事件日志 |

后端采用 `api → services → repositories` 三层架构。推荐从 `api/jobs.py → services/job_service.py → repositories/job_repository.py` 顺着读；业务服务统一管理事务，仓库不自行提交。结构和调用关系见 [后端架构说明](docs/后端架构说明.md)，完整目录见 [项目代码结构与 Agent 开发路线](项目参考代码目录.md)。

MySQL 保存画像、条件、岗位、资料元数据、记忆和已完成报告。画像和岗位字段存入现有 JSON 列。旧岗位原始 JD 会原样转换为 job_description，新的要求、学历和年限保持未知；个人画像缺少必填项时须完善后再评估/面试。报告包括输入快照，之后修改或删除岗位不会重写历史结果。原始文件保存在 `data/uploads/`。

运行、待确认提案、聊天页面消息和未完成面试仅在内存。刷新可重新发现同一服务进程中仍存在的活动；服务重启后未完成活动丢失，需要重新发起。已保存资料和报告不受影响。

上传图片最大 8 MiB，PDF/DOCX 最大 16 MiB；多图逐张上传。服务端请求体另有 48 MiB 上限，413 不自动重试。文件内容检查只验证基本格式，不替代你实现的解析和 OCR。

## 验证

应用测试使用独立 MySQL 实例，每个用例创建独立的 `job_search_agent_test_...` 数据库，用例完成后仅删除自己的测试库，不清理 `.env` 对应的项目库。

```powershell

.\.venv\Scripts\python.exe -X utf8 -m pytest -q
.\.venv\Scripts\python.exe -X utf8 scripts/test_mysql.py stop
```

测试实例仅绑定 `127.0.0.1`，使用随机密码和临时端口，凭据只写入被忽略的 `.runtime/`。启动测试需要已安装 `mysqld`，可以使用现有 MySQL 安装中的可执行文件，不会改动原实例。

测试还包含使用本机 Microsoft Edge 的 Playwright DOM 回归，无需下载浏览器，不截图。只运行后端测试可加 `-m "not browser"`。由 AI 执行浏览器/视觉验收时，仍必须委派子代理并仅回报文字结果。

隔离视觉检查可在测试实例启动后执行 `.\.venv\Scripts\python.exe -X utf8 -m scripts.visual_preview`，访问 `http://127.0.0.1:8001`；该进程使用独立测试库。视觉验收遵守项目约束：由子代理执行，父线程仅接收文字结论。

未保存的画像/条件表单在同一页面会话中保留，普通聊天不会覆盖它们；如果服务器资料已更新，旧表单保存会提示修订冲突，可选择重新读取已保存资料。导入预览可补齐字段或跳过条目；取消会停止尚未发送的请求，已经保存的条目不会回滚，会明确提示数量。

## 常见问题

- **数据库不可用 / 503**：检查 MySQL 是否启动、`.env` 是否正确、项目库是否已初始化。程序不会切换 SQLite。
- **资料已发生变化 / 409**：已有编辑使旧修订失效。刷新后重新操作；聊天提案可拒绝后重新生成，避免覆盖新资料。
- **已有活动 / 409**：先回答当前问题、确认/拒绝提案或结束面试。一次仅有一个活动。
- **真实 Agent 尚未接入 / 503**：按接口说明提供你的入口，或切回演示模式验证页面。
- **端口被占用**：先检查是否已打开启动窗口。不要为了启动本项目强行关闭其他程序。
- **上传失败 / 413**：缩小文件后由你重新选择上传，应用不会自动重复同一请求。

依赖仅安装在 `.venv/`；`.env`、上传、日志、测试实例与运行数据已列入 `.gitignore`。
